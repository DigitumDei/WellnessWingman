## Executive Summary

This branch adds OpenRouter as a new LLM provider, implementing OpenRouterLlmClient for both chat (mirroring OpenAiLlmClient with OpenRouter's base URL and attribution headers) and STT transcription (using OpenRouter's JSON/base64 audio endpoint rather than multipart). The enum, factory, repository, settings UI, and AnalysisOrchestrator providerId path are all wired and compiler-enforced for exhaustiveness. A key early dispute—whether OpenRouter's STT endpoint and JSON/base64 contract were real—was resolved against the blocker: the endpoint, request shape, root `text` response, and `openai/whisper-1` model slug are all confirmed in OpenRouter's live documentation. Remaining issues are non-blocking operational risks and test gaps, none of which prevent merge.

## Non-Blocking Issues

- MIME type fallback maps unsupported formats (webm, ogg, aac, flac) to m4a (shared/src/commonMain/kotlin/com/wellnesswingman/domain/llm/OpenRouterLlmClient.kt): OpenRouter's whisper-1 model accepts webm, ogg, aac, and flac, but transcribeAudio maps any unrecognized mimeType to 'm4a' via an else branch. Sending a WebM recording labeled as m4a will mismatch the bytes and likely produce a server-side error.
- HttpClient and OpenAI client are never closed, leaking resources per analysis (shared/src/commonMain/kotlin/com/wellnesswingman/domain/llm/OpenRouterLlmClient.kt): LlmClientFactory builds a fresh OpenRouterLlmClient per createForCurrentProvider() call. Each instance holds both a Ktor HttpClient and an openai-kotlin OpenAI client, neither of which is ever closed. LlmClient exposes no lifecycle hook, so this is a systemic gap, but the additional unclosed Ktor client is new to this PR.
- responseFormat = JsonObject unconditionally applied when schema is present, incompatible with arbitrary user-configured models (shared/src/commonMain/kotlin/com/wellnesswingman/domain/llm/OpenRouterLlmClient.kt): The settings UI free-texts the model field, and many OpenRouter-routed models do not support response_format: json_object. Misconfiguration will surface as opaque 4xx errors. This matches OpenAI parity, but the free-text model field makes the risk higher for OpenRouter users.
- providerId detection via javaClass.simpleName is brittle under R8/minification and wrappers (shared/src/commonMain/kotlin/com/wellnesswingman/domain/analysis/AnalysisOrchestrator.kt): AnalysisOrchestrator infers the provider by substring-matching the client's runtime class name. The PR adds an 'openrouterllmclient' branch correctly, but this approach breaks under ProGuard/R8 obfuscation or proxy wrappers. Pre-existing smell now extended to the new provider; the 'unknown' fallback is an improvement over the former 'gemini' default.
- Stale review artifact contradicts current implementation and has a trailing blank line (docs/reviews/ask-886-1782500823801/2026-06-27T12-30-39.714Z-review.md): docs/reviews/ask-886-1782500823801/2026-06-27T12-30-39.714Z-review.md describes the prior multipart transcription approach as a blocking defect, which no longer reflects the JSON/base64 implementation. Additionally, git diff --check fails on this file due to a blank line at EOF (line 527). The repo conventionally tracks review transcripts, so the historical record is intentional, but the whitespace error should be fixed if CI enforces diff --check.
- analyzeImage hardcodes data:image/jpeg;base64, prefix regardless of actual image format (shared/src/commonMain/kotlin/com/wellnesswingman/domain/llm/OpenRouterLlmClient.kt): PNG or other image bytes are labeled as image/jpeg in the base64 data URI. Pre-existing parity with OpenAiLlmClient; flagged because it affects the new client identically.
- saveLlmSettings cannot clear a stored API key once set: The non-blank guard on openRouterApiKey persistence means a user cannot erase a saved key from the UI. Mirrors the existing OpenAI/Gemini behaviour; not a regression, but a replicated limitation.
