## Blocking Issues

- ViewModel test contradicts production error behavior (composeApp/src/commonTest/kotlin/com/wellnesswingman/ui/healthchat/HealthChatThreadViewModelTest.kt): The test expects HealthChatThreadUiState.Error, but send() records the failure in sendError and leaves the UI state unchanged, so the test will fail deterministically.
- History trimming can produce orphaned tool results (shared/src/commonMain/kotlin/com/wellnesswingman/healthchat/HealthChatService.kt): When the retention boundary falls on the second or later TOOL message in a multi-result tool round, the backward scan stops at the preceding TOOL message and omits the parent assistant tool-call message. This can produce invalid provider requests during replay.
- API-key recovery after returning from settings is unreliable (composeApp/src/commonMain/kotlin/com/wellnesswingman/ui/healthchat/HealthChatThreadScreen.kt): Navigator-size tracking and remember-scoped state can reset while settings is displayed, causing the return transition to be missed and hiding the manual retry path. Users may remain in ApiKeyMissing without a usable recovery action.

## Non-Blocking Issues

- Malformed tool arguments are converted to empty arguments: All three LLM clients fall back to an empty JSON object instead of returning an explicit parsing error. Production wrappers mitigate many executor failures, but a handler accepting empty arguments could still produce a misleading successful result.
- Raw exception details are persisted and may reach the error snackbar: The transcript replaces failed messages with generic text, but raw exception messages are still stored and propagated through ProviderError, creating unnecessary privacy and implementation-detail exposure.
- HealthChatListViewModel lacks test coverage: Refresh, deletion, cancellation, and partial-failure behavior are untested.
- Error snackbar has no dismissal or retry lifecycle: The custom snackbar remains rendered until another send clears sendError, and configuration recheck does not clear stale errors.
- Cancellation and failure cleanup can be interrupted or replace the original error: Generic failure cleanup is not consistently protected by NonCancellable, and repository failures during cleanup are not guarded.
- Unused Compose UI-test dependency: The added compose.uiTest dependency is not used by the current tests.

## Missing Tests

- A history-trimming test where the boundary falls within multiple TOOL results from one assistant tool-call round.
- A Compose navigation test covering settings push/pop and API-key rechecking.
- HealthChatListViewModel tests for successful loads, deletion, cancellation, and refresh/deletion failures.
- LLM-client tests for malformed tool arguments and executor failures during generateChatResponse.
- Cleanup failure tests for cancellation and ordinary provider-error paths.

## Disputed Issues

- The severity of malformed tool-argument handling is disputed: reviewers agree it is a regression, but disagree whether production wrappers make it blocking.
- The severity of raw exception-message exposure is disputed because the transcript masks it, while the database and snackbar paths still retain or propagate it.
- The correlated SQL query and conversation-ID collision concerns were not supported strongly enough to classify as actionable defects.

## Outstanding Concerns

- The LLM-client tool-argument parsing behavior remains unsafe for direct callers and can yield misleading tool results.
- Raw provider and exception details should be sanitized before persistence or user-facing error propagation.
